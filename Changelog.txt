This this the changelog file for the Pothos C++ library.

pothos2 (in development)
==========================

Repository:

- Only the core: the toolkit submodules (audio, blocks, comms, flow,
  plotters, python, soapy, widgets, spuce), sync_toolkits and the 0.7
  debian packaging are removed; the toolkits live in their own repositories
- find_package(Pothos) finds the core added with add_subdirectory or
  FetchContent (for the parent and the toolkits next to it)
- Topology::commit() throws TopologyConnectError naming the missing block
  when a domain crossing (/blocks/copier) or a flow across hosts
  (/blocks/network_*) needs PothosBlocks and it is not installed

Expressions (EvalEnvironment):

- Built-in expression evaluator replaces muparserx (submodule removed)
- Python-like syntax, a superset of JSON: None/null, True/true, lists, dicts,
  chained comparisons, and/or/not, x if c else y, indexing
- Incompatible: ^ is bitwise xor, use ** for power (2^3 is now 1)
- Incompatible: / always gives a float, // is floor division
- Incompatible: octal literals need the 0o prefix (0315 is an error)
- Integer overflow is an error, unknown names are always an error
- Decimal integer literals beyond 64 bits (JSON uint64 numbers) are floats
- Duplicate dict keys: the last value wins

Build (CMake):

- The core works as a subproject (add_subdirectory/FetchContent): prefixed
  options and cache entries (POTHOS_NUMA_LIBRARY, POTHOS_CAN_COMPILE_*, ...),
  no change to the parent's globals; tests only when POTHOS_BUILD_TESTS=ON;
  documentation target pothos_docs; no uninstall target in a parent project
- Options renamed/removed: ENABLE_LIBRARY, ENABLE_LIBRARY_LIB,
  ENABLE_LIBRARY_INCLUDE, ENABLE_LIBRARY_CMAKE removed; ENABLE_LIBRARY_APPS
  -> POTHOS_BUILD_APPS; ENABLE_LIBRARY_DOCS -> POTHOS_BUILD_DOCS; new
  POTHOS_BUILD_TESTS; APPDATA_ENV -> POTHOS_APPDATA_ENV
- No global CMAKE_CXX_STANDARD or RPATH settings any more (target properties)

Public API (source compatible for blocks):

- BufferChunk::asSpan<T>() gives a std::span<T> view of the buffer
  (length / sizeof(T) elements; as<T>() and the pointer conversion stay)
- Util::SpinLock waits (std::atomic_flag::wait) instead of spinning when
  contended; ports and registries use std::mutex/std::shared_mutex
- Removed: Pothos/Util/SpinLockRW.hpp (use std::shared_mutex)
- Util::index_sequence, make_index_sequence, index_sequence_for,
  integer_sequence, special_decay_t and unwrap_refwrapper are aliases of
  the standard ones; typedefs in the headers became using-declarations
- POTHOS_TEST_EQUAL/NOT_EQUAL/LT/LE/GT/GE compare C strings by content
  (null pointers are allowed) and integers of mixed signedness correctly
- Config.hpp no longer includes <ciso646>
- Fixed: extracting a null Object no longer dereferences a null pointer
- The core builds without warnings on GCC and Clang; POTHOS_WARNINGS_AS_ERRORS

SIMD:

- libsimdpp replaced by xsimd (vendored in third_party/xsimd): CPU feature
  detection and SIMD buffer conversion; the feature names stay the same
  (x86_sse2, x86_avx2, ...); x86_xop and mips_msa are no longer detected

PothosUtil and dependencies:

- Poco removed: PothosUtil has its own command line parser, termination
  handling, daemon mode and Windows service support
- Command line: --opt=value and --opt value; options are parsed first and
  commands run in command line order (option order no longer matters)
- Unix: --daemon, --umask, --pidfile; Windows: --register-service[=NAME],
  --unregister-service[=NAME], --display-name, --description, --startup
  (the service keeps the other options of the registering command line)
- The Windows termination event of PothosUtil is PothosUtilTerminate<pid>

Networking:

- Remote client/server, the PothosUtil proxy server and syslog forwarding
  run on a built-in network layer over standalone Asio (Poco Net removed)
- Syslog forwarding sends RFC 5424 with the source and level as structured
  data ([pothos@32473 ...]); the listener accepts RFC 5424 and RFC 3164
  and listens on IPv6 and IPv4

Release 0.6.0 (2017-12-25)
==========================

- Updated internal poco submodule to poco-1.8.0.1-release
- Removed deprecated API call OutputPort::popBuffer()
- Re-implement RingDeque container to use std::allocator
- Removed previously unused ObjectM class (mutable object)
- Added Pothos::Util::SpinLockRW for single write, multi-read
- API changes to Object, Proxy, and Callable interface types
  * Object supports implicit templated convert to target type
  * Proxy supports implicit templated convert to target type
  * Deprecated Callable interface's callVoid(), use call()
  * Deprecated Callable interface's callObject(), use call()
  * Deprecated Proxy interface's callVoid(), use call()
  * Deprecated Proxy interface's callProxy(), use call()
- Automatic slots for all void calls in Block::registerCallable:
  Previously calls with 1 or more arguments became automatic slots.
  The new rule checks for void return type and supports calls
  without arguments. In addition registerSlot() will not throw
  when registering slots that were created automatically.
- Renamed the project repo from pothos to PothosCore
- Updated toolkit/submodule URLs for repo rename
  - Renamed pothos-gui toolkit to PothosFlow
  - Renamed pothos-sdr toolkit to PothosSoapy
- Alternative JSON C++ library to handle JSON parsing/emitting
