# Phase 17: PothosAudio on the pothos2 core with miniaudio — plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The fork `markvin/PothosAudio` (branch `pothos2`) builds
against the installed pothos2 core 2.0 with a copy of miniaudio in place
of PortAudio, keeps the block API, has self-tests on the null backend of
miniaudio and CI, and is a submodule of PothosBase.

**Architecture:** miniaudio is compiled once in an internal static
library (a C file with `MINIAUDIO_IMPLEMENTATION`, only device I/O). Small
helpers (backend selection, device lookup, format and int8 conversion,
interleave) have their own files and unit tests. `AudioBlock` owns a
miniaudio context, one device and a `ma_pcm_rb` ring buffer between the
device callback and `work()`.

**Tech Stack:** C++23 and C (miniaudio 0.11), CMake ≥ 3.25 (tested on
4.4), nlohmann_json ≥ 3.11 (`find_package`), Conan 2 (core, blocks,
json), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-31-phase17-audio-design.md`

## Review Focus

- A device that disappears or fails while the graph runs (USB microphone
  unplugged): the block must not hang `work()` or `deactivate()`; it
  reports an error. Test: Task 2 `test_audio_stop_without_data` (the
  source `work()` returns when no frames come, and `deactivate()` returns
  within 1 s).
- `numChans` larger than the device has (stereo from a mono microphone):
  miniaudio converts; the block must still produce `numChans` channels.
  Test: Task 2 source test with `numChans = 2` and `PORTPERCHAN` (two
  output ports with data).
- A slow downstream (the source overflows): frames are dropped in the
  callback, `work()` reports `aO` once per event, the graph continues.
  Test: Task 2 `test_audio_source_overflow` (a source with no consumer
  for 500 ms, then data flows again and a LOGGER record "overflow").
- An old topology with a PortAudio device name: a clear exception that
  names the device. Test: Task 2 `test_audio_device_select` (the unknown
  name is in the exception text).
- Two audio blocks in one process (source and sink in one graph, the
  use case of the user): two devices at the same time on one backend.
  Test: Task 2 `test_audio_loop_graph` (source → sink on the null
  backend runs for 300 ms without an error).

  `findDevice`, config with `formatFromDType` (u8 for int8),
