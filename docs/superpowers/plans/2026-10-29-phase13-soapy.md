# Phase 13: PothosSoapy on the pothos2 core — plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The fork `markvin/PothosSoapy` (branch `pothos2`) builds
against an installed pothos2 core and SoapySDR without Poco and without
warnings. Its self-tests move data through `/soapy/sink` and
`/soapy/source` with a test driver, and it has CI. Then PothosBase
builds it as a submodule.

**Architecture:** The CMake of soapy follows PothosComms: CMake 3.25,
`find_package(Pothos ... NO_PACKAGE_ROOT_PATH)`, `find_package(SoapySDR
0.8 CONFIG)`, a stage install and `--self-test1` runs of each test with
the `PothosUtil` of the core. A `SoapySDR::Device` test driver in
`tests/` is registered only inside a test through a scoped
`SoapySDR::Registry`. CI gets the core dependencies from Conan and builds
SoapySDR `soapy-sdr-0.9.0` from upstream source into a cached prefix.

**Tech Stack:** C++23, CMake ≥ 3.25 (tested on 4.4), SoapySDR (≥ 0.8;
local Arch 0.8.1, CI 0.9.0), nlohmann_json ≥ 3.11, Conan 2 (core and
json), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-29-phase13-soapy-design.md`

  `yield()`. The sink writes with `txTime`/`txEnd` labels as
  `SOAPY_SDR_HAS_TIME`/`SOAPY_SDR_END_BURST`. The format string comes
  from the dtype (`complex_float32` → `CF32`, `complex_int16` → `CS16`).

  `setGain`/`getGain<i>`/`getGainNames<i>`, `setGainMode`/
  `getGainMode<i>`, `setAntenna`/`getAntenna<i>`/`getAntennas<i>`,
  `setBandwidth`/`getBandwidth<i>`, `setDCOffsetMode`/
  `getDCOffsetMode<i>`; global `setSampleRate`/`getSampleRate`,
  `setClockSource`/`getClockSource`, `setTimeSource`, `setClockRate`/
  `getClockRate`, `setGlobalSetting`, `setLogLevel`.
- `/devices/soapy/info` returns a JSON string: `"SoapySDR info"` →
  `"Factories"` (names from `Registry::listFindFunctions()`, joined by
  `", "`); `"SDR Device"` from `Device::enumerate()` without args.
- `SoapySDR::Registry::~Registry()` erases its entry (0.8.1 source).
- `Topology::waitInactive(idleDuration = 0.1, timeout = 1.0)`. The
  source yields on each timeout; if `waitInactive` does not return true
  in the loopback test, wait for the collector instead (Task 2 Step 1).
- Comms CI (`PothosComms/.github/workflows/ci.yml`) checks out and
  installs PothosBlocks into the core prefix; widgets CI has the RPATH
  check step for a library outside the system directories.

## Review Focus

1. The source starts before the sink writes, or the FIFO of the driver
   is empty for a time: the source gives no data, does not throw, and the
   data comes later in order. Test: Task 2 Step 1 `test_loopback_cf32`
   (the source and sink start together; the check is on the full,
   ordered data).
2. A user enumerates devices (`SoapySDRUtil --find`, the overlay of the
   blocks, `/devices/soapy/info`) with soapy installed: the test driver
   never shows. Test: Task 2 Step 1 `test_driver_registration` (no entry
   after the scope; `enumerate()` without args does not give it during
   the scope).
3. SoapySDR is installed in a prefix that is not a system directory
   (CI, a user build): the installed modules load from the stage prefix.
   Test: Task 5 Step 2 RPATH check in CI and Task 4 Step 2 locally.
4. SoapySDR 0.9 (no `<ciso646>`): the workaround is off and the build is
   clean with `-Werror`. Test: Task 4 Step 2.
5. A setter that the driver does not support (for example a gain name
   that does not exist): the block gives the exception of the driver to
   the caller and does not hang. Test: Task 2 Step 1
   `test_settings` last check.
