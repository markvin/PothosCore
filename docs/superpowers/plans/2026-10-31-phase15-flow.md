# Phase 15: PothosFlow on the pothos2 core — plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The core gets a public log listener API and has no known data
races. The fork `markvin/PothosFlow` (branch `pothos2`) builds against
the installed pothos2 core with Qt 6, has no Poco and no warnings, and a
smoke test without a display shows that the application starts, shows
the About window and stops cleanly. Then PothosBase builds flow as a
submodule.

**Architecture:** The listener API goes into `Pothos/System/Logger.hpp`:
the internal `Detail::LogRecord` becomes the public `LogRecord`, and the
listeners are called in `writeToSink` under the sink lock, after the
sink. The race fixes use `std::atomic<bool>` and `std::map::find`. In
flow, the application sources go into an internal static library; the
`PothosFlow` executable and the smoke test executable link it and share
the start code (`FlowSetup`). The message window uses a core listener in
place of a `Poco::Channel`.

**Tech Stack:** C++23, CMake ≥ 3.25 (tested on 4.4), Qt 6 (≥ 6.5; local
Arch 6.12, CI 6.5.3 / 6.8.3 on Windows; components Widgets and
Concurrent), Conan 2 (core and blocks only), GitHub Actions, TSan (GCC
or Clang, local only).

**Spec:** `docs/superpowers/specs/2026-10-31-phase15-flow-design.md`

- [ ] **Step 3: Implement the API**

- `LogRecord` and `LogListener` in `Logger.hpp` before `class Logger`,
  with Doxygen comments that give the rules of the spec ("Core: log
  listener API", rules 1–6). `<chrono>`, `<functional>`, `<string>`
  includes. No other include.
- `LoggerState`: `std::map<std::size_t, LogListener> listeners` and
  `std::size_t nextListenerId = 1`, both under `sinkMutex` (all
  listener calls run under `sinkMutex`, thus `removeListener` waits for a
  call in progress).
- `writeToSink`: call the sink if it is not empty, then each listener in
  id order, each in `try`/`catch (...)`. Set a `thread_local bool
  inListener` during the listener calls.
- Nested log: at the start of `dispatch`, if `inListener` is true, put
  the record into a `thread_local std::vector<LogRecord> nestedRecords`
  and return. `writeToSink`, after the listener loop and still under the
  lock, writes the nested records to the sink only (not to the
  listeners), and clears them. Thus no `flush()` and no second lock in
  the listener thread.
- `addListener`/`removeListener` from inside a listener (`inListener`
  true): do not lock `sinkMutex` (the thread has it); put the change into
  a `thread_local` list that `writeToSink` applies after the listener
  loop. Document this in the comment.
- `addListener` and `removeListener` take `sinkMutex` with `lock_guard`
  in the normal case. Do not call `Logger::flush()` in them.

- [ ] **Step 1: Write the smoke test `FlowSmokeTest.cpp`**

`main`: `FlowProcessSetup`, `QApplication`, `configureFlowApplication`,
a core listener that records all records at Error level or worse, then
the checks. Each check prints `PASS <name>` or `FAIL <name>: <reason>`
and a failure returns exit code 1. A `QTimer` of 120 s ends the process
with `FAIL timeout` and exit code 1.

1. `window_visible`: `new MainWindow(nullptr)`; wait (event loop) until
   `isVisible()`.
2. `block_cache`: wait for `BlockCache::global()->blockDescReady`
   (connect before the window is made, or check the cache if it is
   already full); `getBlockDescFromPath("/blocks/copier")` is not empty.
   Then `QThreadPool::globalInstance()->waitForDone(60000)` is true (the
   host explorer work is complete).
3. `about_window`: a single-shot `QTimer` (100 ms, repeated until found)
   finds a visible top-level `QMessageBox` with `windowTitle() == "About
   Pothos"`; on Linux and Windows also
   `QApplication::activeModalWidget()` is that box; on macOS print
   `INFO about window is not modal on macOS (QMessageBox::about)`. Then
   `box->accept()`. Trigger `showAboutAction` after the timer is set
   (`exec()` blocks on Linux and Windows).
4. `message_window`: `POTHOS_LOG_INFO("PothosFlow.SmokeTest", "smoke-marker-<pid>")`,
   `Logger::flush()`, process events until the text of the message
   window (`MainWindow::global()->findChildren<QPlainTextEdit *>()` or
   `QTextEdit`, the widget that `LoggerDisplay` uses) contains the
   marker, max 10 s.
5. `exit`: `window->close()`, `delete window` (this runs
   `Pothos::deinit()` and stops the server), then
   `app.processEvents()`. `errors`: the listener got no record at Error
   level or worse. Remove the listener, return 0.
